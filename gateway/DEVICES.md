# Adding devices after launch

Use this Linux tool on a gateway generated by provision.py. It reads existing
peer assignments and allocates a free address. Names and public keys must
be unique per gateway. Each region has an independent registry. Keep the
initial provisioning copies archived; the installed config is authoritative.

In WireGuard for Windows, the new tester chooses Add empty tunnel. The app
generates a key pair. Obtain their **public** key through your normal
authenticated enrollment channel. The private key stays on the device.

On the gateway, substitute the public key in the enrollment command:

    sudo python3 gateway/devices.py /etc/wireguard/wg-london.conf add lab-laptop PUBLIC_KEY
    sudo python3 gateway/devices.py /etc/wireguard/wg-london.conf list
    sudo wg show wg-london public-key

Give the tester their assigned address, the gateway public key from the
last command, and the public endpoint. In their empty tunnel keep the
existing PrivateKey line, then enter the other settings as shown:

    [Interface]
    PrivateKey = EXISTING_DEVICE_PRIVATE_KEY
    Address = ASSIGNED_ADDRESS_WITH_32_PREFIX
    DNS = 1.1.1.1

    [Peer]
    PublicKey = GATEWAY_PUBLIC_KEY
    Endpoint = GATEWAY_PUBLIC_IPV4:51820
    AllowedIPs = 0.0.0.0/0, ::/0
    PersistentKeepalive = 25

After activation use Test-Exit.ps1 for the live pilot report. For removal:

    sudo python3 gateway/devices.py /etc/wireguard/wg-london.conf remove lab-laptop

Edits are serialized and the saved config is replaced atomically. Live mode
reloads the wg-quick systemd unit. If reload fails, the command exits with
an error; retry after fixing the service. Until reload succeeds the live
peer state can differ from disk. Use wg show to confirm live revocations.
For an offline copy outside /etc/wireguard, specify --offline before add
or remove. The list command shows device names and addresses only.
